# Stability

Tern follows [semantic versioning](https://semver.org). From v1.0.0, minor and patch releases do not break code that uses the public API described here. Breaking changes happen only in major versions, are listed in the [changelog](../CHANGELOG.md), and come with a migration note.

## What the promise covers

| Area | Covered |
|---|---|
| **Route conventions** | `src/routes`, `+page.svelte`, `+layout.svelte`, `+error.svelte`, the `.param`, `.optional`, `.rest` and `.group` directory suffixes, and the exported names `Load`, `LayoutLoad`, `Actions`, `GET` (and other methods), `SSR`, `Prerender` and `Entries` |
| **`kit` for application code** | `Ctx` and its methods, `LoadOf`, `Action`, `Actions`, `Parent`, `Defer` and `Deferred`, `Error`, `NotFound`, `Redirect`, `Fail` and their error types, `App`, `New`'s options (`With…`), `Plugin` and `Setup` |
| **Built-in plugins** | Everything under `plugins/` |
| **`@ternkit/tern`** | Everything exported from `@ternkit/tern` and `@ternkit/tern/vite` |
| **Generated modules** | The names exported from `./$types` (`PageProps`, `PageData`, `LayoutProps`, `LayoutData`, `ActionData`, `RouteParams`, …) and from `$routes` (`route`, `base`, `Routes`, `RoutePattern`) |
| **Wire format** | How Go types map to TypeScript, the placeholders in `src/app.html`, and `tern.json` |
| **CLI** | The `tern` commands and their flags |
| **Runtime behavior** | The documented behavior in the [guide](guide.md), such as when loads rerun and which headers are sent |

## What it does not cover

- **The generated-code interface**: `kit.Manifest`, `LayoutDef`, `RouteDef`, `PageDef`, `FallbackDef`, and the `@ternkit/tern/client`, `/server` and `/polyfills` entry points. `tern.gen.go` and `.tern/` are regenerated by the CLI, and `go get -tool` keeps the CLI and `kit` at the same version, so these can change in any release.
- **Packages under `internal/`**, which Go prevents other modules from importing.
- **The exact HTML and JSON Tern produces**, beyond what is documented: markup details, the data request format, and log messages may change.
- **Unsupported setups**: Go and Node.js versions older than those in the README, and Svelte or Vite majors that `@ternkit/tern` does not list as peer dependencies.

## Deprecation

When something is going to be removed, it is first marked `Deprecated:` in its doc comment (Go) or `@deprecated` (TypeScript) for at least one minor release, with the replacement named, before the next major version removes it.

## Supported versions

Security and bug fixes go to the latest minor release. After a new major version, the previous major gets security fixes for six months.
