## Project structure

```
my-app/
├── src/
│   ├── app.html            HTML template
│   ├── lib/                shared Svelte and TypeScript code, imported as $lib
│   └── routes/             your pages, layouts and server code
├── static/                 files served as-is (favicon, robots.txt, …)
├── main.go                 starts the server
├── go.mod                  pins the Tern CLI with a `tool` directive
├── package.json
├── tsconfig.json           extends .tern/tsconfig.json
└── vite.config.js          uses the tern() plugin
```

Tern generates `tern.gen.go` and the `.tern/` directory. Both are gitignored and regenerated by `tern dev`, `tern build` and `tern gen`.

`src/app.html` must contain `%tern.head%` and `%tern.body%`. It may also use `%tern.nonce%`, the per-request nonce Tern puts on its own scripts, for example in a Content-Security-Policy `<meta>` tag.

## Routing

Every directory under `src/routes` is a URL segment. A directory becomes a page when it has a `+page.svelte`.

| Directory | URL |
|---|---|
| `src/routes/` | `/` |
| `src/routes/about/` | `/about` |
| `src/routes/blog/slug.param/` | `/blog/:slug` |

Go import paths cannot contain brackets, so dynamic segments use suffixes instead of SvelteKit's notation. `tern routes` and error messages still show patterns in bracket notation.

| Directory | Pattern | Matches |
|---|---|---|
| `slug.param` | `[slug]` | `/hello` |
| `id.param.integer` | `[id=integer]` | `/42`, but not `/abc` |
| `lang.optional` | `[[lang]]` | `/` and `/en` |
| `path.rest` | `[...path]` | `/`, `/a`, `/a/b/c` |
| `app.group` | (none) | nothing: groups organize routes without changing URLs |

When several routes match a URL, the most specific wins: static segments beat parameters, parameters with a matcher beat those without, required beats optional, and rest parameters come last. Two routes that match exactly the same URLs are an error.

**Matchers** restrict a parameter. `integer` and `uuid` are built in; register your own in `main.go`:

```go
ternApp(kit.WithMatcher("slug", regexp.MustCompile(`^[a-z0-9-]+$`).MatchString))
```

**Route files.** Svelte files that start with `+` define the UI; everything else in a route directory is yours.

| File | Purpose |
|---|---|
| `+page.svelte` | the page |
| `+layout.svelte` | wraps this directory's page and every page below it |
| `+error.svelte` | renders errors for this directory and below |
| `*.go` | the route's server code, an ordinary Go package |

Colocated components, styles and Go helpers are fine. The route's Go package does whatever its exports say:

| Export | Role |
|---|---|
| `func Load(ctx *kit.Ctx) (T, error)` | data for `+page.svelte` |
| `func LayoutLoad(ctx *kit.Ctx) (T, error)` | data for `+layout.svelte` |
| `var Actions = kit.Actions{…}` | form actions for the page |
| `func GET(ctx *kit.Ctx) error` (and `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `HEAD`) | endpoint handlers |
| `const SSR = false` | render this page on the client only |
| `const Prerender = true` | render this page to static HTML at build time |
| `func Entries(ctx *kit.Ctx) ([]map[string]string, error)` | parameters to prerender a dynamic route with; `ctx` is optional |

By convention the code lives in `page.server.go`, `layout.server.go` and `server.go`, but file names do not matter. Because route directories are normal Go packages, `go test ./...`, `go vet`, gopls and linters work on them as usual.

## Loading data

A page's `Load` runs on the server for every request to the page, and for client-side navigations to it:

```go
// src/routes/blog/slug.param/page.server.go
package post

import "github.com/Unfield/Tern/kit"

type Data struct {
	Title string `json:"title"`
	Body  string `json:"body"`
}

func Load(ctx *kit.Ctx) (Data, error) {
	post, err := db.PostBySlug(ctx, ctx.Param("slug")) // *kit.Ctx is a context.Context
	if errors.Is(err, sql.ErrNoRows) {
		return Data{}, kit.NotFound()
	}
	if err != nil {
		return Data{}, err
	}
	return Data{Title: post.Title, Body: post.Body}, nil
}
```

```svelte
<!-- src/routes/blog/slug.param/+page.svelte -->
<script lang="ts">
	import type { PageProps } from './$types';
	let { data }: PageProps = $props();
</script>

<h1>{data.title}</h1>
```

The data type must encode to a JSON object: a struct, a pointer to a struct, or a map with string keys. It is encoded with `encoding/json`, so struct tags work as usual.

`*kit.Ctx` gives you the request:

| Method | Returns |
|---|---|
| `ctx.Param(name)`, `ctx.Params()` | route parameters |
| `ctx.URL()`, `ctx.Request` | the request URL and the full `*http.Request` |
| `ctx.Header(name)` | a request header |
| `ctx.Cookie(name)` | a request cookie |
| `ctx.SetCookie(c)`, `ctx.DeleteCookie(name)` | set cookies; `Path=/`, `SameSite=Lax` and `Secure` (except on plain-HTTP localhost) by default |
| `ctx.SetHeader(name, value)` | set a response header |
| `ctx.Locals` | request-scoped values, usually set by a hook |
| `ctx.Form()` | the submitted form, in actions |

## Layouts

A `+layout.svelte` wraps every page in its directory and below. It renders its page with `children`:

```svelte
<script lang="ts">
	import type { LayoutProps } from './$types';
	let { data, children }: LayoutProps = $props();
</script>

<nav>Signed in as {data.user}</nav>
{@render children()}
```

A layout loads data with `LayoutLoad` in its directory's Go package. Every page below it receives that data merged into its own `data`, and layouts receive the data of the layouts above them.

All loads for a page run **in parallel**. A load that needs a parent layout's data calls `kit.Parent`, which waits only for the layouts above it:

```go
type Parent struct {
	User string `json:"user"`
}

func Load(ctx *kit.Ctx) (Data, error) {
	parent, err := kit.Parent[Parent](ctx)
	if err != nil {
		return Data{}, err
	}
	return loadDashboard(ctx, parent.User)
}
```

A directory with a `LayoutLoad` but no `+layout.svelte` still contributes data; it just does not add markup.

## Errors and redirects

Return these errors from loads, actions, endpoints and hooks:

| Error | Response |
|---|---|
| `kit.NotFound()` | 404, rendered by the nearest `+error.svelte` |
| `kit.Error(status, message)` | that status; `message` is shown to the user |
| `kit.Redirect(status, location)` | a redirect (use 303 after form posts) |
| any other error | logged; the user sees 500 "Internal Error" |
| a panic | recovered, logged, and treated like an unexpected error |

`+error.svelte` reads the error from `page`:

```svelte
<script lang="ts">
	import { page } from '@ternkit/tern';
</script>

<h1>{page.status}</h1>
<p>{page.error?.message}</p>
```

The error page renders inside the layouts above it that loaded successfully. Unexpected error messages are never sent to the browser in production; in `tern dev` they are, to help debugging.

## Form actions

Actions handle `POST` requests from forms on a page:

```go
type Created struct {
	ID int `json:"id"`
}

type Invalid struct {
	Title string `json:"title"`
	Error string `json:"error"`
}

var Actions = kit.Actions{
	"create": kit.Action(func(ctx *kit.Ctx) (Created, error) {
		form, err := ctx.Form()
		if err != nil {
			return Created{}, err
		}
		title := strings.TrimSpace(form.Get("title"))
		if title == "" {
			return Created{}, kit.Fail(400, Invalid{Title: title, Error: "Title is required"})
		}
		return Created{ID: db.Create(ctx, title)}, nil
	}),
}
```

```svelte
<script lang="ts">
	import { enhance } from '@ternkit/tern';
	let { data, form }: PageProps = $props();
</script>

<form method="POST" action="?/create" use:enhance>
	<input name="title" value={form?.title ?? ''} />
	<button>Create</button>
</form>
{#if form?.error}<p>{form.error}</p>{/if}
```

- A form without `?/name` runs the `"default"` action.
- The action's result, or the data passed to `kit.Fail`, becomes the page's `form` prop. Its type is generated from the actions and every `kit.Fail` call in the package.
- **Without JavaScript**, the browser posts the form and Tern re-renders the page with `form` set.
- **With `use:enhance`**, the form posts in the background. On success it resets the form and reruns the page's loads, then sets `form`. On failure it sets `form`. Redirects and errors behave as on a normal navigation.

To customize `use:enhance`, pass a function:

```svelte
<form method="POST" use:enhance={() => {
	submitting = true;
	return async ({ update }) => {
		await update({ reset: false });
		submitting = false;
	};
}}>
```

## Endpoints

Export HTTP method handlers to serve JSON, files, feeds or webhooks:

```go
// src/routes/api/posts/server.go
package posts

func GET(ctx *kit.Ctx) error {
	posts, err := db.Posts(ctx)
	if err != nil {
		return err
	}
	return ctx.JSON(200, posts)
}
```

- `ctx.JSON` and `ctx.Text` write common responses; `ctx.Writer()` gives you the `http.ResponseWriter` for anything else.
- A handler that writes nothing responds `204 No Content`.
- `HEAD` falls back to `GET`, and unsupported methods get `405` with an `Allow` header.
- A directory can have both a page and endpoints. Browser requests (`Accept: text/html`) and form posts go to the page; other requests go to the endpoint.


### Typed endpoints

An endpoint can declare its input and output types instead of writing the response itself. `tern gen` then describes it in an OpenAPI document, and in a typed client for your components:

```go
type ListQuery struct {
	Search string `json:"q,omitempty"`
	Status string `json:"status,omitempty"`
}

func GET(ctx *kit.Ctx, in ListQuery) ([]Project, error) { ... }

type NewProject struct {
	Name string `json:"name"`
}

func (p *NewProject) Validate() error { // optional; its error becomes a 400
	if p.Name == "" {
		return errors.New("name is required")
	}
	return nil
}

func POST(ctx *kit.Ctx, in NewProject) (Project, error) { ... }
```

- **Signatures:** `func(ctx *kit.Ctx) (Out, error)` and `func(ctx *kit.Ctx, in In) (Out, error)` are typed. `func(ctx *kit.Ctx) error` stays a plain endpoint.
- **Where input comes from:** query parameters for GET, HEAD and DELETE; a JSON body for other methods.
  - Query fields are named by their `query` tag, else their `json` name.
  - Supported query field types: strings, numbers, booleans, `time.Time`, pointers, and slices from repeated parameters.
  - Fields tagged `path:"id"` come from the route's parameters.
- **Failures:** invalid input is answered with 400, a body that isn't JSON with 415, and errors work as in other endpoints.
- **Output:** written as JSON.

Call them from components with `$api`. The endpoint, parameters, query, body and result are all type-checked:

```svelte
<script lang="ts">
	import { ApiError } from '@ternkit/tern';
	import { api } from '$api';

	async function add(name: string) {
		try {
			const project = await api('POST /api/projects', { body: { name } });
		} catch (e) {
			if (e instanceof ApiError) alert(e.message); // the server's message; e.status has the code
		}
	}
</script>
```

`kit.WithOpenAPI("/api/openapi.json", "Acme API", "1.0.0")` serves the OpenAPI 3.1 document. It has paths, parameters, request bodies and response schemas, with components for your Go structs, so you can generate clients for other languages or browse it with any OpenAPI tool.

## Hooks, middleware and configuration

`main.go` creates the app with the generated `ternApp` function and configures it with options:

```go
func main() {
	app, err := ternApp(
		kit.WithHook(auth),
		kit.WithMiddleware(requestLogger),
		kit.WithLogger(slog.New(slog.NewJSONHandler(os.Stdout, nil))),
	)
	if err != nil {
		log.Fatal(err)
	}
	log.Fatal(app.ListenAndServe())
}

// auth runs before every page, data, action and endpoint request.
func auth(ctx *kit.Ctx) error {
	if user, ok := sessions.User(ctx); ok {
		ctx.Locals["user"] = user
	}
	return nil
}
```

| Option | Effect |
|---|---|
| `kit.WithHook(fn)` | run `fn(ctx)` before every request; return an error such as `kit.Redirect` to stop it |
| `kit.WithMiddleware(mw...)` | wrap the app in `func(http.Handler) http.Handler` middleware |
| `kit.WithMatcher(name, fn)` | add a parameter matcher |
| `kit.WithTrustedOrigins(...)` | allow cross-origin form posts from these origins |
| `kit.WithoutCSRFProtection()` | disable cross-origin request protection |
| `kit.WithBodyLimit(n)` | maximum request body size (default 1 MiB) |
| `kit.WithLogger(l)` | the `*slog.Logger` for errors and server events |
| `kit.WithAddr(addr)` | the listen address (default `HOST:PORT` from the environment, port 3000) |
| `kit.WithContentSecurityPolicy(policy)` | send a Content-Security-Policy with a per-request script nonce |
| `kit.WithoutSSR()` | render every page on the client only |
| `kit.WithSSRWorkers(n)`, `kit.WithSSRTimeout(d)` | tune server rendering |

`*kit.App` is an `http.Handler`, so you can also mount it in your own server or router instead of calling `ListenAndServe`.

## Plugins

Plugins package reusable server behavior. Add them in `main.go`:

```go
import (
	"github.com/Unfield/Tern/plugins/compress"
	"github.com/Unfield/Tern/plugins/health"
	"github.com/Unfield/Tern/plugins/requestlog"
	"github.com/Unfield/Tern/plugins/secure"
)

app, err := ternApp(kit.WithPlugins(
	health.New(health.Check("database", db.PingContext)),
	requestlog.New(requestlog.SkipAssets()),
	compress.New(),
	secure.New(secure.HSTS(365*24*time.Hour, true)),
))
```

| Plugin | What it does |
|---|---|
| `plugins/health` | `GET /healthz` for liveness and `GET /readyz` for readiness, running your checks with a timeout. Readiness reports 503 during shutdown so load balancers drain first. |
| `plugins/requestlog` | One structured `slog` line per request: method, path, status, duration and size. |
| `plugins/compress` | gzip for HTML, JSON, XML and text responses. Streaming still flushes as values resolve. |
| `plugins/secure` | Security headers: no framing, a strict referrer policy, browser features off, cross-origin isolation, and opt-in HSTS. |
| `plugins/sessions` | Encrypted cookie sessions (AES-GCM): `sessions.Get(ctx).Set("user", id)`, `GetString`, `Value`, flash messages, and secret rotation with `OldSecrets`. |
| `plugins/metrics` | Prometheus metrics at `/metrics`: requests by route and status, a latency histogram, in-flight requests and Go runtime stats. Routes are labeled by pattern, so the number of series stays bounded. |
| `plugins/ratelimit` | A token bucket per client; by default only form actions and other writes are limited. Over the limit: 429 with `Retry-After`. |
| `plugins/cors` | CORS for endpoints, including preflights; the allowed origins are also trusted by cross-site request protection. |
| `plugins/oauth` | Sign in with GitHub, Google or any OpenID Connect provider. See [Authentication](#authentication). |
| `plugins/oidc` | Make your app an OAuth 2.0 and OpenID Connect provider. See [Authentication](#authentication). |

Plugins can also serve routes with a `Ctx` (`Setup.Endpoint`), start work with the server (`Setup.OnStart`), and exempt cookie-free endpoints from cross-site protection (`Setup.AllowCrossOrigin`).

### Writing a plugin

A plugin is any type with `Name() string` and `Setup(*kit.Setup) error`. `Setup` can register:

| Method | Adds |
|---|---|
| `s.Hook(fn)` | a hook that runs before every request |
| `s.Middleware(mw)` | `net/http` middleware |
| `s.Matcher(name, fn)` | a parameter matcher |
| `s.TrustOrigin(origin)` | an origin allowed to make cross-site writes |
| `s.Handle(pattern, h)` | an `http.Handler`, served before routes (`"GET /metrics"`) |
| `s.Head(html)`, `s.HeadFunc(fn)` | HTML in every page's `<head>`; `HeadFunc` gets the CSP nonce for inline scripts |
| `s.OnShutdown(fn)` | work to do when the server stops |

```go
type Analytics struct{ SiteID string }

func (Analytics) Name() string { return "analytics" }

func (a Analytics) Setup(s *kit.Setup) error {
	s.HeadFunc(func(_ *kit.Ctx, nonce string) string {
		return fmt.Sprintf(`<script defer nonce="%s" src="https://stats.example.com/script.js" data-site="%s"></script>`, nonce, a.SiteID)
	})
	return nil
}
```

Plugins are set up in order after the other options, and each name may only be added once.

## Types

`tern gen` (run automatically by `tern dev` and `tern build`) generates a `$types.d.ts` for every route from your Go types:

```ts
import type { PageProps, LayoutProps, PageData, ActionData, RouteParams } from './$types';
```

Conversion follows `encoding/json` exactly:

| Go | TypeScript |
|---|---|
| `string`, `bool`, numbers | `string`, `boolean`, `number` |
| `time.Time`, types with `MarshalText` | `string` |
| `[]byte` | `string` (base64) |
| `[]T`, `map[string]T`, `*T` | `Array<T> \| null`, `Record<string, T> \| null`, `T \| null` (nil encodes as `null`) |
| `[N]T` | `Array<T>` |
| named structs | `interface` declarations |
| `omitempty`, `omitzero` | optional fields |
| `json:",string"` | `string` |
| `kit.Deferred[T]` | `Promise<T>` |
| interfaces, types with `MarshalJSON` | `unknown` |

`tern gen` also checks the signatures of your exports and reports mistakes at the right line, before the Go compiler sees the generated code.

## Rendering

Pages render on the server and hydrate in the browser. Users see content before JavaScript loads, search engines see real HTML, and forms work without JavaScript.

Server rendering runs your Svelte components in an embedded JavaScript engine inside the Go binary (QuickJS, pure Go, no cgo). Browser APIs like `window` and `document` are not available while rendering; use them in `onMount` or `$effect`, which only run in the browser. This matches the rules for SvelteKit.

Besides the JavaScript language, code that runs during rendering can use:

- `URL` and `URLSearchParams`
- `TextEncoder` and `TextDecoder` (UTF-8), `atob` and `btoa`
- `crypto.getRandomValues` and `crypto.randomUUID`, backed by Go's `crypto/rand`
- `structuredClone`
- `Event`, `CustomEvent`, `EventTarget`, `AbortController` and `AbortSignal`
- `performance.now()` and `queueMicrotask`
- `console`, which logs through the app's logger, and `process.env.NODE_ENV`
- an `Intl` that formats like `en-US`; the browser re-renders with the user's real locale

Timers (`setTimeout`, `setInterval`) can be called but never fire, as in any server renderer: the HTML is sent when the render returns. `fetch` rejects with an explanation; load data in Go instead.

The server bundle resolves libraries without the `node` export condition, so they use their portable builds rather than ones that need Node's `Buffer` or `node:crypto`. A few packages only have a portable build under the `browser` condition; Tern uses it for `nanoid`, and `tern({ ssrBrowserBuilds: ['some-package'] })` in `vite.config.js` adds others.

Every push renders these libraries in Tern and checks the HTML is identical to Node's: bits-ui, @lucide/svelte, svelte-sonner, mode-watcher, paneforge, runed, @tanstack/svelte-query, date-fns, dayjs, marked, highlight.js, KaTeX, nanoid, uuid, zod, valibot, d3, floating-ui, clsx, tailwind-merge, lodash, svelte-i18n and layerchart (see [tests/ssr-compat](../tests/ssr-compat)).

Rendered HTML is cached by the page's data and URL (32 MiB by default, `kit.WithSSRCache`), so a page that looks the same for many visitors renders once. Keep what a component renders on the server a function of its data: output that depends on the clock or `Math.random()` does not hydrate cleanly, and it could be served from the cache.

If a server render fails or exceeds 5 seconds, Tern logs the error and sends the page for client rendering instead, so a rendering bug does not take the page down.

To render a page only on the client, add `const SSR = false` to its route package. `kit.WithoutSSR()` does this for the whole app.

## Streaming

Wrap slow data in `kit.Defer` so the page does not wait for it:

```go
type Data struct {
	Post     Post                     `json:"post"`
	Comments kit.Deferred[[]Comment] `json:"comments"`
}

func Load(ctx *kit.Ctx) (Data, error) {
	post, err := db.Post(ctx, ctx.Param("slug"))
	if err != nil {
		return Data{}, err
	}
	return Data{
		Post:     post,
		Comments: kit.Defer(ctx, func() ([]Comment, error) { return db.Comments(ctx, post.ID) }),
	}, nil
}
```

```svelte
{#await data.comments}
	<p>Loading comments…</p>
{:then comments}
	{#each comments ?? [] as c}<Comment {c} />{/each}
{:catch error}
	<p>Could not load comments: {error.message}</p>
{/await}
```

The function starts immediately. The page renders and is sent with the pending state, and the value streams to the browser when it resolves. Errors reject the promise; unexpected error messages are hidden as usual.

## Prerendering

Pages whose content is the same for everyone can be rendered once at build time:

```go
package about

const Prerender = true
```

For dynamic routes, list the parameters:

```go
package post

const Prerender = true

func Entries() ([]map[string]string, error) {
	slugs, err := db.AllSlugs(context.Background())
	if err != nil {
		return nil, err
	}
	entries := make([]map[string]string, len(slugs))
	for i, s := range slugs {
		entries[i] = map[string]string{"slug": s}
	}
	return entries, nil
}
```

Endpoints can be prerendered too, for files such as `sitemap.xml` or `feed.xml`: add `const Prerender = true` to a route package with a `GET` handler. The URL needs a file extension, so the static file gets the right type.

`tern build` saves each page's HTML and data into the binary and serves them as static files with ETags. Prerendered pages still hydrate and navigate on the client, and their form actions still run on the server. Hooks do not run for prerendered pages, so only prerender pages that are public.

## Typed links

`tern gen` writes a `$routes` module with every route's URL pattern. Build links with `route()` instead of string templates:

```svelte
<script lang="ts">
	import { route } from '$routes';
</script>

<a href={route('/projects/[id]', { id: project.id })}>{project.name}</a>
```

TypeScript checks that the pattern exists and that required parameters are given, so renaming a route directory turns every stale link into a compile error. Optional parameters (`[[lang]]`) may be left out, and rest parameters (`[...path]`) accept a string or an array of segments. Parameter values are URL-encoded.

## The client API

Import from `@ternkit/tern` in your components:

| Export | Purpose |
|---|---|
| `page` | reactive state for the current page: `url`, `params`, `route.id`, `status`, `error`, `data`, `form`, `state` |
| `env` | the server's `PUBLIC_` environment variables, such as `env.PUBLIC_API_URL`; other variables never reach the browser |
| `navigating.current` | the navigation in progress, or `null` |
| `goto(href, opts)` | navigate; options: `replaceState`, `noScroll`, `keepFocus`, `invalidateAll`, `state` |
| `invalidate(key)` | rerun the loads that called `ctx.Depends(key)`, and the page's load |
| `invalidateAll()` | rerun every load for the current page |
| `beforeNavigate(fn)` | run before each navigation; `nav.cancel()` stops it (for example with unsaved changes) |
| `onNavigate(fn)` | run before the new page renders; return a promise to delay it (view transitions) or a function to run afterwards |
| `afterNavigate(fn)` | run after each navigation, including the first page load |
| `preloadData(href)` | load a page's data and code ahead of time |
| `enhance` | progressive form enhancement (`use:enhance`) |
| `applyAction(result)` | apply an action result as `use:enhance` does |

Links to pages in the app navigate on the client. These attributes change link behavior, on the link or any ancestor:

| Attribute | Effect |
|---|---|
| `data-tern-preload="hover"` | preload when the pointer rests on a link (the starter template sets this on `<body>`) |
| `data-tern-preload="tap"` | preload on mousedown or touch (the default) |
| `data-tern-preload="off"` | never preload |
| `data-tern-reload` | always do a full page load |
| `data-tern-noscroll` | keep the scroll position |
| `data-tern-replacestate` | replace the history entry instead of adding one |

Links with `target`, `download`, `rel="external"`, or another origin are left to the browser. Forms with `method="GET"`, such as search boxes, also navigate on the client; when they target the current page, focus and scroll position are kept so typing is not interrupted. After each navigation, Tern restores scroll positions on back and forward, moves focus to the document, and announces the new page title to screen readers.

## Reloading data

On a client-side navigation, Tern reruns a layout's load only when something it used changed:

| Used in the load | Reruns when |
|---|---|
| `ctx.Param("id")` | that parameter changes |
| `ctx.URL()` | the URL (path or query) changes |
| `kit.Parent[T](ctx)` | a parent layout reruns |
| `ctx.Depends("app:projects")` | the browser calls `invalidate('app:projects')` |

Other layouts are reused from the browser's copy, so moving between pages under a layout does not repeat its queries. The page's own load always runs. Full page loads, form actions and `invalidateAll()` run every load.

Reading `ctx.Request` directly is not tracked. If a layout depends on the request in a way Tern cannot see (for example a header), call `ctx.URL()` or `ctx.Depends` so it reruns when needed, or use `invalidateAll()` after the change.

```go
func LayoutLoad(ctx *kit.Ctx) (Shell, error) {
	ctx.Depends("app:projects")
	return loadShell(ctx)
}
```

```svelte
<button onclick={() => invalidate('app:projects')}>Refresh</button>
```

## Content Security Policy

`kit.WithContentSecurityPolicy("default-src 'self'")` sends a `Content-Security-Policy` header on every page. Tern adds a fresh nonce to `script-src` for each request and puts it on its own scripts, so strict policies work without `'unsafe-inline'`. Use `%tern.nonce%` in `src/app.html` for your own inline scripts. `kit.WithContentSecurityPolicyReportOnly` sends the report-only header to try a policy first.

Libraries that inject inline scripts during server rendering (for example a dark-mode script) need the nonce too; check whether they accept one, or move their script into `app.html` with `nonce="%tern.nonce%"`.

## Static files and assets

- Files in `static/` are served at the root: `static/robots.txt` is `/robots.txt`.
- Assets you import are processed by Vite and get content-hashed names: `import logo from '$lib/logo.svg'`.
- Hashed files are cached by browsers for a year; everything else revalidates with ETags. Text assets are precompressed with gzip.

## Authentication

Tern's building blocks for sign-in work together: `plugins/sessions` remembers who is signed in, `plugins/oauth` signs users in with other providers, `plugins/oidc` lets other apps sign in with yours, and `rbac` checks permissions.

### Sign in with GitHub, Google or OpenID Connect

```go
oauth.New(oauth.Options{
	Secret: secret, // at least 32 bytes; the sessions secret works
	Providers: []*oauth.Provider{
		oauth.GitHub(os.Getenv("GITHUB_CLIENT_ID"), os.Getenv("GITHUB_CLIENT_SECRET")),
		oauth.Google(os.Getenv("GOOGLE_CLIENT_ID"), os.Getenv("GOOGLE_CLIENT_SECRET")),
		oauth.OIDC("company", "Company SSO", "https://sso.example.com", clientID, clientSecret),
	},
	OnLogin: func(ctx *kit.Ctx, id oauth.Identity) error {
		user, err := users.FindOrCreate(ctx, id.Provider, id.Subject, id.Email)
		if err != nil {
			return err
		}
		return sessions.Get(ctx).Set("user", user.ID)
	},
})
```

A link to `/auth/github/login?next=/dashboard` starts the sign-in. Register `https://your.app/auth/github/callback` as the redirect URL with the provider. After `OnLogin`, the user lands on `next`. `next` must be a path on your site, which prevents open redirects. If the user cancels, or the sign-in fails, they go to `/login?error=<code>` (`ErrorURL`).

- **Flow security:** every sign-in uses PKCE and a `state` value, plus a nonce for OpenID Connect. These travel in a short-lived encrypted cookie.
- **Token checks:** ID tokens are verified against the provider's published keys.
- **Identifying users:** look users up by `Provider` and `Subject`. Use the email only if `EmailVerified` is true.
- **Identity fields:** `Identity` also carries the provider's claims and its OAuth token, for calling its API.
- **Proxies:** behind a proxy that changes the host, set `URL` to the app's public address.

### Be an OpenID Connect provider

With `plugins/oidc`, your app is the place users sign in. Other apps (your other services, a wiki, a mobile app, a single-page app) send users to it and get tokens back:

```go
store, _ := oidc.NewSQLStore(db)
provider := oidc.New(oidc.Options{
	Issuer: "https://auth.example.com",
	Store:  store,
	Clients: []oidc.Client{
		{ID: "wiki", Secret: os.Getenv("WIKI_SECRET"), Name: "Team wiki",
			RedirectURIs: []string{"https://wiki.example.com/oauth/callback"}},
		{ID: "mobile", Public: true, Trusted: true, RedirectURIs: []string{"com.example.app:/callback"}},
		{ID: "billing", Secret: os.Getenv("BILLING_SECRET"), GrantTypes: []string{"client_credentials"}, Scopes: []string{"api:read"}},
	},
	Scopes:   []string{"api:read", "api:write"},
	LoginURL: "/login", // signed-out users go here with ?next=
	Authenticate: func(ctx *kit.Ctx) (string, error) {
		return sessions.Get(ctx).GetString("user"), nil
	},
	Claims: func(ctx context.Context, subject string, scopes []string) (map[string]any, error) {
		u, err := users.Get(ctx, subject)
		return map[string]any{"email": u.Email, "email_verified": true, "name": u.Name}, err
	},
})
```

**Endpoints:**

| Endpoint | What it does |
|---|---|
| `/.well-known/openid-configuration` | Discovery |
| `/oauth/jwks` | Signing keys |
| `/oauth/authorize` | Sign-in and consent |
| `/oauth/token` | Issues tokens |
| `/oauth/userinfo` | The user's claims |
| `/oauth/revoke` | Revocation (RFC 7009) |
| `/oauth/introspect` | Introspection (RFC 7662) |

**Flows:**
- **Authorization code with PKCE:** PKCE is required for public clients, and only S256 is accepted. The authorization response includes `iss` (RFC 9207).
- **Refresh tokens:** they rotate on every use. A refresh token used twice revokes every token from that sign-in, since the reuse means one was stolen.
- **Client credentials:** for services that act as themselves rather than for a user.

**Tokens:** access tokens are RS256 JWTs (`typ: at+jwt`, RFC 9068), and ID tokens are RS256 JWTs.

**Consent:** apps that aren't `Trusted` get a consent screen, which can't be framed. The answer is remembered for each user and app.

**Validation:** before anything is redirected, the client and its exact redirect URI are checked, so the endpoint can't send users to arbitrary sites. Codes and refresh tokens are stored only as hashes.

**Your own APIs:** protect them with the provider's tokens:

```go
func GET(ctx *kit.Ctx) error {
	token, err := provider.Bearer(ctx, "api:read") // 401 or 403 with WWW-Authenticate
	if err != nil {
		return err
	}
	return ctx.JSON(200, projectsOf(token.Subject))
}
```

Other services can verify the same tokens against `/oauth/jwks`, or ask `/oauth/introspect`. The signing key is created on first start and kept in the store. `MemoryStore` forgets everything on restart, so use `NewSQLStore` in production.

### Roles and permissions

```go
var policy = rbac.New(map[string][]string{
	"viewer": {"projects:read"},
	"editor": {"role:viewer", "projects:write"},
	"admin":  {"*"},
}, func(ctx *kit.Ctx) []string {
	return currentUser(ctx).Roles // nil when signed out
})

func Load(ctx *kit.Ctx) (Page, error) {
	if err := policy.Require(ctx, "projects:read"); err != nil {
		return Page{}, err // 401 signed out, 403 without the permission
	}
	...
}
```

- **Wildcards:** `"projects:*"` grants every `projects:` permission.
- **Role includes:** `"role:viewer"` includes another role's permissions.
- **Checks in components:** `policy.Can(ctx, perm)` returns a bool, for showing or hiding parts of a page.
- **Guarding a section:** `kit.WithHook(policy.Hook("/admin", "admin:access"))` guards everything under `/admin`.

## Databases

Tern doesn't choose a database library for you: use `database/sql`, sqlc, GORM or anything else in your loads and actions. Its own database packages work with SQLite and PostgreSQL through `database/sql`, with any driver (such as `modernc.org/sqlite` or `github.com/jackc/pgx/v5/stdlib`), and detect which one you use.

### Database migrations

`tern migrate new add users` creates `migrations/<timestamp>_add_users.sql`. Write the change, and optionally an `-- +down` section that undoes it:

```sql
CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT NOT NULL);

-- +down
DROP TABLE users;
```

Embed the directory and apply pending migrations when the server starts:

```go
//go:embed migrations/*.sql
var migrations embed.FS

app, err := ternApp(kit.WithPlugins(migrate.Plugin(db, migrations)))
```

Each migration runs in a transaction and is recorded in `tern_migrations`. If a migration fails, the server doesn't start. Editing a migration after it was applied is reported as an error (`migrate.ErrChanged`); add a new one instead. On PostgreSQL, instances starting at the same time take turns. `migrate.Up`, `migrate.Down` and `migrate.Status` are available for your own tooling.

### Background jobs

The `jobs` package runs work outside requests, such as sending email, with retries. Jobs are stored in your database, so they survive restarts, and instances sharing a database run each job once:

```go
q, err := jobs.New(db, jobs.Options{})

sendWelcome := jobs.Handle(q, "email.welcome", func(ctx context.Context, u User) error {
	return mailer.Send(ctx, u.Email, "Welcome!")
}, jobs.MaxAttempts(5), jobs.Timeout(time.Minute))

app, err := ternApp(kit.WithPlugins(q))
```

```go
// In an action, after creating the user:
if _, err := sendWelcome.Enqueue(ctx, user); err != nil {
	return err
}
```

- The payload is stored as JSON and decoded into the handler's type.
- A handler that returns an error or panics is retried with exponential backoff (about 1s, 4s, 16s, and so on, up to an hour) until it has run `MaxAttempts` times.
- `jobs.Delay(d)` and `jobs.At(t)` run a job later. `jobs.Unique("reminder:42")` skips enqueueing while a job with the same key is queued or running. `jobs.InTx(tx)` enqueues inside your transaction, so the job only exists if it commits.
- The workers start with the server, after migrations, and stop when it shuts down. Running jobs get the shutdown timeout to finish.
- `q.Stats`, `q.List` and `q.Retry` let you build an admin page.

### Scheduled tasks

```go
q.Schedule("cleanup", "0 3 * * *", func(ctx context.Context) error {
	return deleteExpiredSessions(ctx, db)
})
q.Schedule("ping", "@every 30s", checkMonitors)
```

Schedules take five-field cron expressions (`*/5 * * * *`, `0 9 * * mon-fri`), `@hourly`, `@daily`, `@weekly`, `@monthly` and `@every <duration>`. They run in UTC unless `Options.Location` says otherwise. Each run is a job, retried like any other. With several instances, each run happens once, and a run doesn't start while the previous one is still going.

## Email

Write emails as Svelte components in `src/emails/`. They render on the server with the same engine as pages. Their styles are included in the HTML, since mail clients can't load your stylesheets. The `<title>` becomes the subject:

```svelte
<!-- src/emails/Welcome.svelte -->
<script module lang="ts">
	export const preview = { name: 'Ada', link: 'https://example.com/confirm?t=demo' };
</script>

<script lang="ts">
	let { name, link }: { name: string; link: string } = $props();
</script>

<svelte:head><title>Welcome, {name}</title></svelte:head>

<h1>Welcome, {name}!</h1>
<p><a href={link}>Confirm your email address</a> to get started.</p>

<style>
	h1 { font-family: system-ui, sans-serif; }
</style>
```

Render and send it from Go with the `mail` package:

```go
mailer := mail.New(mail.SMTP{Host: "smtp.example.com", Port: 587, Username: user, Password: pass}, "Acme <hello@acme.com>")

msg, err := mailer.Template(ctx, app, "Welcome", map[string]any{"name": u.Name, "link": link})
msg.To = []string{u.Email}
err = mailer.Send(ctx, msg)
```

**The message:** it carries the HTML and a plain-text version made from it (links appear as `text (url)`). `app.RenderEmail` returns these parts without sending.

**SMTP:**
- Port 465 uses TLS from the start. Other ports require STARTTLS unless `Insecure` is set, for local servers such as Mailpit.
- Addresses are validated, `Bcc` recipients never appear in the headers, and line breaks can't inject headers.

**Development:**
- Use `&mail.Log{}` as the transport to print messages instead of sending them.
- `/__tern/emails` lists every template, and `/__tern/emails/<Name>` previews one with its `preview` props. Add `?text` for the text version.
- Previews update as you edit the templates.

**Retries:** send in the background with `mail.Job`:

```go
sendMail := mail.Job(q, mailer) // a jobs kind, retried up to five times
_, err := sendMail.Enqueue(ctx, *msg)
```

## File uploads and storage

The `storage` package keeps files in a `Bucket`: a directory on disk (`storage.Disk("data/files")`) or an S3-compatible bucket, such as AWS S3, Cloudflare R2, MinIO or Backblaze B2:

```go
files, err := storage.NewS3(storage.S3Options{
	Endpoint: "https://s3.eu-central-1.amazonaws.com", Region: "eu-central-1", Bucket: "acme",
	AccessKey: os.Getenv("S3_ACCESS_KEY"), SecretKey: os.Getenv("S3_SECRET_KEY"),
})
```

Receive files in a form action with `storage.Receive`. It raises the request's body limit to fit, checks sizes, and detects each file's type from its contents rather than trusting the browser:

```go
"default": kit.Action(func(ctx *kit.Ctx) (struct{}, error) {
	uploads, err := storage.Receive(ctx, "avatar", storage.ReceiveOptions{MaxSize: 5 << 20, Types: []string{"image/png", "image/jpeg", "image/webp"}})
	var invalid *storage.InvalidUpload
	if errors.As(err, &invalid) {
		return struct{}{}, kit.Fail(400, Invalid{Error: invalid.Message})
	}
	if err != nil {
		return struct{}{}, err
	}
	key := storage.NewKey("avatars", uploads[0].Filename) // avatars/2026/11/3f9a…-portrait.png
	return struct{}{}, uploads[0].Save(ctx, files, key)
}),
```

```svelte
<form method="POST" enctype="multipart/form-data" use:enhance>
	<input type="file" name="avatar" accept="image/*" />
	<button>Upload</button>
</form>
```

Serve the files with the `storage.Serve` plugin:

```go
signer := storage.NewSigner(secret)
kit.WithPlugins(storage.Serve("/files/", files, storage.ServeOptions{Signer: signer}))

url := signer.URL("/files/", key, time.Hour) // a link that expires
```

- **Signed links:** with a `Signer`, every file is private. Only signed, unexpired links work.
- **Unsafe file types:** files are sent with `nosniff` and a sandboxing Content Security Policy. Only images, media, PDF and plain text display inline; HTML, SVG and everything else download. An uploaded file can't run scripts on your site.
- **Range requests:** disk files support them, for video.
- **S3:** files are redirected to short-lived presigned URLs, so downloads don't pass through your app.
- **Direct uploads:** `bucket.PresignPut(key, ttl)` lets browsers upload large files straight to S3.

S3 requests are signed with AWS Signature Version 4. The signing is tested against AWS's published examples, and in CI against an S3-compatible server (SeaweedFS).

## Realtime

### Server-sent events

`ctx.EventStream` keeps a response open and pushes events to the browser. It sends a keep-alive comment every 20 seconds and ends when the client disconnects or the server shuts down:

```go
func GET(ctx *kit.Ctx) error {
	return ctx.EventStream(func(ctx context.Context, s *kit.EventStream) error {
		for {
			select {
			case <-ctx.Done():
				return nil
			case <-time.After(time.Second):
				if err := s.Send("tick", map[string]any{"at": time.Now()}); err != nil {
					return err
				}
			}
		}
	})
}
```

`Send` encodes data as JSON, or sends strings as they are. `SendEvent` also sets an `ID`, which the browser sends back as `LastEventID()` when it reconnects, and a `Retry` delay.

In components, `stream` from `@ternkit/tern` subscribes and keeps the latest value in reactive state:

```svelte
<script lang="ts">
	import { stream } from '@ternkit/tern';
	let { data } = $props();
	const clock = stream<{ at: string }>('/api/clock', { events: ['tick'], initial: data.clock });
</script>

<p>{clock.current?.at} ({clock.status})</p>
```

It doesn't connect during server rendering, where `current` is the `initial` value, and it closes when the component is destroyed. The browser reconnects by itself after errors.

### WebSockets

`ctx.WebSocket` upgrades an endpoint request. `Receive` and `Send` read and write JSON; `ReceiveText`, `SendText` and `Conn` give lower-level access:

```go
func GET(ctx *kit.Ctx) error {
	return ctx.WebSocket(nil, func(ctx context.Context, ws *kit.WebSocket) error {
		for {
			var msg ChatMessage
			if err := ws.Receive(&msg); err != nil {
				return err // a closed connection ends the handler without an error being logged
			}
			hub.Publish("chat", msg)
		}
	})
}
```

Only pages on the app's own origin can connect; list other origins in `WebSocketOptions.Origins`. When the server shuts down, connections are closed with "going away". In components, `socket` connects, queues messages sent while connecting, decodes JSON and reconnects with backoff:

```svelte
<script lang="ts">
	import { socket } from '@ternkit/tern';
	const chat = socket<ChatMessage, ChatMessage>('/api/chat', { onMessage: (m) => messages.push(m) });
</script>
```

### Publish and subscribe

The `realtime` package connects the parts of an app that change things with the browsers watching them:

```go
var hub = realtime.NewHub[MonitorStatus]()

// When a check finishes:
hub.Publish("monitors", status)

// An endpoint that streams the topic to the browser:
func GET(ctx *kit.Ctx) error { return realtime.Stream(ctx, hub, "monitors") }
```

`hub.Subscribe(ctx, topic)` returns a channel for your own WebSocket or stream handlers. Subscribers that fall more than `Buffer` messages behind miss messages instead of slowing publishers down. The hub is in memory; to run several instances, implement `realtime.Broker` with Redis, NATS or Postgres `LISTEN/NOTIFY` and use `realtime.NewHubWith`.

Under `tern dev`, your WebSockets are served by the Go app; only Vite's own connection goes to Vite.

## Markdown and content

### Markdown pages

A `+page.md` file is a page written in Markdown. `tern gen` renders it to HTML, and it is wrapped in the directory's layouts like any page. Front matter `title` and `description` become the page's `<title>` and meta description:

```markdown
---
title: Privacy
description: What we store about you.
---
# Privacy

We store **nothing** you didn't type.
```

A directory has either a `+page.md` or a `+page.svelte`. The component's module exports `metadata` (the front matter) and `headings`.

### Content collections

For blogs, docs and changelogs, put Markdown files in `src/content/<collection>/` and read them in Go with the `content` package. Front matter is YAML, decoded into your struct:

```go
package blog

type Post struct {
	Title string    `yaml:"title" json:"title"`
	Date  time.Time `yaml:"date" json:"date"`
}

var Posts = &content.Collection[Post]{
	Dir:  "blog",
	Sort: content.Newest(func(p Post) time.Time { return p.Date }),
}

func Load(ctx *kit.Ctx) (List, error) {
	posts, err := Posts.Summaries(ctx) // without bodies, for list pages
	return List{Posts: posts}, err
}
```

```go
package post

const Prerender = true

func Entries(ctx *kit.Ctx) ([]map[string]string, error) { /* Posts.Slugs(ctx) */ }

func Load(ctx *kit.Ctx) (content.Entry[blog.Post], error) {
	return blog.Posts.Get(ctx, ctx.Param("slug")) // 404 if there is no such post
}
```

```svelte
<h1>{data.data.title}</h1>
<article>{@html data.html}</article>
```

An `Entry` has the `Slug` (the file path without `.md`, with `guides/index.md` as `guides`), the decoded `Data`, the rendered `HTML`, the `Headings` for a table of contents, an `Excerpt` and `ReadingMinutes`.

- `src/content` is embedded in the binary and read once. Under `tern dev` it is read from disk on every request, so edits show on reload.
- Files with `draft: true` in their front matter are left out in production but shown under `tern dev`. Files starting with `_` are skipped.

Markdown is rendered with [goldmark](https://github.com/yuin/goldmark): GitHub-flavored Markdown (tables, task lists, autolinks, strikethrough), footnotes, smart quotes, heading IDs and highlighted code blocks. Highlighting uses CSS classes; `content.CodeCSS("github")` returns a stylesheet for them in any [chroma style](https://xyproto.github.io/splash/docs/). Raw HTML in your Markdown is kept, as in a `.svelte` file. For Markdown that users write, use `content.Render`, which escapes HTML.

## Images

Add `?image` to an image import and Tern resizes it to several widths in AVIF, WebP and its own format. Show it with `<Image>`, which renders a `<picture>` with the right sources, its width and height (so the page does not shift while it loads) and lazy loading:

```svelte
<script lang="ts">
	import { Image } from '@ternkit/tern';
	import hero from '$lib/assets/hero.jpg?image';
</script>

<Image src={hero} alt="The team at work" sizes="(min-width: 1024px) 50vw, 100vw" />
```

- By default the widths are 640, 1280 and 1920 pixels, those smaller than the image, plus the image's own width. Choose others with `?w=400,800&image`.
- `sizes` tells the browser how wide the image is shown, so it downloads the smallest file that is sharp enough. Without it, the browser assumes the image's full width.
- `priority` loads the image at once with high priority; use it for the main image above the fold. Other images load lazily.
- Images with transparency keep PNG as the fallback format; others use JPEG.

**Remote images.** `<Image>` also takes the URL of an image on another site, with the width and height it is shown at:

```svelte
<Image src="https://images.unsplash.com/photo-123" width={800} height={533} alt="A lake" />
```

The `plugins/images` plugin resizes them on the fly for the srcset, and caches the results:

```go
kit.WithPlugins(images.New(images.Options{Hosts: []string{"images.unsplash.com"}}))
```

- **What it fetches:** only HTTPS images on the listed hosts (`*.example.com` matches subdomains), up to 20 MB and 50 megapixels.
- **Sizes:** images are never enlarged.
- **Formats:** remote images are re-encoded as JPEG, or PNG when they have transparency, because Go has no pure-Go AVIF or WebP encoder.

Images are encoded with [sharp](https://sharp.pixelplumbing.com/), which you install in your app: `npm install -D sharp`. In development each size is encoded the first time the browser asks for it. Encoded files are cached in `node_modules/.cache/tern-images`, so builds only encode new or changed images. Their names come from the image's contents, and they are served with the other hashed assets, cached for a year.

## Translations

Put one JSON file per locale in `src/locales`, such as `en.json` and `de.json`. Nest keys as you like; `t()` uses dotted paths:

```json
{
	"login": { "title": "Sign in", "invalid": "Enter a name of up to {max} characters." },
	"projects": { "count": "{count, plural, =0 {No projects} one {# project} other {# projects}}" }
}
```

Translate in components with `t` from `@ternkit/tern`. `tern gen` types its keys from the default locale, so a typo is a type error:

```svelte
<script lang="ts">
	import { t } from '@ternkit/tern';
	let { data } = $props();
</script>

<h1>{t('login.title')}</h1>
<p>{t('projects.count', { count: data.projects.length })}</p>
```

Messages use a subset of ICU MessageFormat: `{name}` placeholders, `plural` (with `=N` cases, CLDR categories such as `one`, `few` and `many`, and `#` for the number) and `select`. Quote literal braces with apostrophes: `'{'`. Go and the browser share one implementation, tested against the same cases, so server-rendered text always hydrates.

**Choosing the locale.** For each request Tern uses the first of:

1. a `lang` route parameter, as in `src/routes/lang.optional/…`
2. the `locale` cookie
3. the best match for the `Accept-Language` header
4. the default locale: `"en"` if there is an `en.json`, else the first file, or `"i18n": { "defaultLocale": "de" }` in `tern.json`

The locale fills `%tern.lang%` in `app.html` (`<html lang="%tern.lang%">`). Only the current locale's messages, and the default locale's for fallbacks, are sent to the browser. A message missing from a locale falls back to the default locale; `tern gen` warns about missing keys.

**In Go**, `ctx.Locale()` returns the locale and `ctx.T` translates, for example for validation errors returned with `kit.Fail`:

```go
return nil, kit.Fail(400, Invalid{Error: ctx.T("login.invalid", map[string]any{"max": 40})})
```

`ctx.SetLocale` overrides the locale for the rest of the request.

**Switching languages.** `setLocale('de')` stores the choice in the `locale` cookie and reloads the page's data without a full page load. `i18n.locale` and `i18n.locales` list the current and available locales for a switcher. If the locale is in the URL instead, link to the other URL.

## Service workers

Add `src/service-worker.ts` and Tern builds it to `/service-worker.js` and registers it in production. The `$service-worker` module tells it what this build contains:

| Export | Contents |
|---|---|
| `build` | URLs of the hashed JavaScript, CSS and asset files |
| `files` | URLs of the files in `static/` |
| `prerendered` | URLs of the prerendered pages |
| `version` | a string that changes with every build, for naming caches |
| `base` | the base path |

```ts
/// <reference no-default-lib="true"/>
/// <reference lib="esnext" />
/// <reference lib="webworker" />
import { build, files, prerendered, version } from '$service-worker';

const sw = self as unknown as ServiceWorkerGlobalScope;
const CACHE = `app-${version}`;

sw.addEventListener('install', (event) => {
	event.waitUntil(caches.open(CACHE).then((c) => c.addAll([...build, ...files, ...prerendered])));
});
```

`examples/todos/src/service-worker.ts` is a complete offline-first worker: cached assets and prerendered pages, the network first for everything else, and the cache when offline.

The service worker is built after prerendering, so its lists are complete. It is not registered in development, where a caching worker would serve stale modules; test it with `tern build`. To register it yourself, set `"serviceWorker": { "register": false }` in `tern.json`.

## Configuration file

Tern works without configuration. An optional `tern.json` at the project root holds the few settings that the Go server, the code generator and Vite must agree on:

```json
{
	"basePath": "/app",
	"i18n": { "defaultLocale": "en" },
	"serviceWorker": { "register": true }
}
```

**`i18n.defaultLocale`** chooses the default locale (see Translations).

**`basePath`** serves the app under a URL prefix, for example behind a proxy that routes `/app/*` to it. With it set:

- the app answers at `/app`, `/app/projects` and so on, and `/` redirects to `/app`
- asset URLs, `%tern.assets%` in `app.html`, and `route()` links include the prefix
- `kit.Redirect(303, "/login")` redirects to `/app/login`; use `ctx.Path("/login")` for other links built in Go
- links outside the prefix are full page loads

Write links with `route()` from `$routes` and `href="%tern.assets%/favicon.svg"` in `app.html`, so the app works with or without a base path.

## Commands

`tern new <dir>` starts a project; `-template blog` adds Markdown posts with an RSS feed, and `-template api` typed JSON endpoints with OpenAPI.

Run the CLI with `go tool tern`, which uses the version pinned in your `go.mod`:

| Command | Purpose |
|---|---|
| `tern dev [-port 5173] [-host localhost]` | development server: hot module replacement for Svelte, automatic rebuilds and reloads for Go, build errors shown in the browser |
| `tern build [-o build/app]` | production binary with the client, server renderer and prerendered pages embedded |
| `tern gen` | regenerate `tern.gen.go`, the client manifest and types |
| `tern routes [dir]` | list routes |
| `tern new [-module path] <dir>` | create a project |
| `tern version` | print the version |

For deployment, see [deployment.md](deployment.md).
